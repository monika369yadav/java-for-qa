First: What is Java?

Java fundamentals, before Selenium.

Java is a programming language used to create applications, websites' backend systems, Android applications, automation frameworks, etc.

For QA, Java is especially useful because tools/frameworks such as Selenium, TestNG, Rest Assured, and many automation frameworks can be used with Java.

For example, instead of manually opening a website and clicking Login, Java + Selenium can do:

LoginTest.java
> driver.findElement(By.id("username")).sendKeys("monika");
> driver.findElement(By.id("password")).sendKeys("12345");
> driver.findElement(By.id("login")).click();
✓ ready to automate

But before Selenium, you need to understand Java fundamentals.

Suite 01

1. Java Introduction + JDK, JRE, JVM

What happens when we write Java code?

Suppose we write:

Hello.java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello Java");
    }
}

Java doesn't directly execute this .java file.

There are three important things:

JDK → JRE → JVM

Think of them like this:

JDK
JRE
JVM

JVM — Java Virtual Machine

JVM is responsible for running Java bytecode.

When you write:

System.out.println("Hello Java");

and compile it, Java creates:

Hello.class

The .class file contains bytecode.

JVM reads this bytecode and executes it.

JRE — Java Runtime Environment

JRE provides the environment needed to run Java applications.

It contains:

JRE = JVM + Java Libraries

If you only want to run Java programs, JRE is the runtime environment.

JDK — Java Development Kit

JDK is what developers/test automation engineers normally install because it contains tools needed to develop and run Java programs.

Simplified:

JDK = JRE + Development Tools

For example, the Java compiler:

javac

is included with the JDK.

Easy example

Imagine you want to make a cake:

JDK = complete kitchen + tools
JRE = kitchen/environment needed to use the cake
JVM = machine that actually processes/runs the Java program

Interview question

Q: What is the difference between JDK, JRE and JVM?

Simple answer:

JDK is used to develop Java applications, JRE provides the environment to run Java applications, and JVM executes Java bytecode.

Suite 06

6. switch

switch is useful when you have multiple fixed choices.

For example:

Day.java
int day = 2;

switch (day) {
    case 1:
        System.out.println("Monday");
        break;

    case 2:
        System.out.println("Tuesday");
        break;

    case 3:
        System.out.println("Wednesday");
        break;

    default:
        System.out.println("Invalid day");
}
Output
Tuesday

Why break?

Without break, Java may continue executing the following cases.

Think:

switch↓ find matching case↓ execute it↓ break↓ exit switch

When should you use if-else vs switch?

Use if-else when you're checking conditions:

if (age >= 18)

Use switch when you're selecting between fixed values:

case 1
case 2
case 3

7. Loops

Loops are used when you want to repeat something.

For example, imagine you want to print:

Goal
Hello
Hello
Hello
Hello
Hello

Instead of writing:

Repeat.java
System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");
System.out.println("Hello");

you can use a loop.

for loop

Syntax:

For.java
for (initialization; condition; update) {
    // code
}

Example:

For.java
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}
Output
1
2
3
4
5

Let's understand it carefully.

Step 1

int i = 1;

Start with 1.

Step 2

i <= 5

Check whether 1 is less than or equal to 5.

True → execute.

Step 3

i++

Increase by 1.

So:

1
2
3
4
5

Then:

i = 6

Condition:

6 <= 5

False → stop.

while loop

A while loop repeats while a condition is true.

While.java
int i = 1;

while (i <= 5) {
    System.out.println(i);
    i++;
}
Output
1
2
3
4
5

Difference:

for     → useful when you generally know how many times to repeat

while   → useful when repetition depends mainly on a condition

do-while loop

The important difference is:

do-while executes at least once.

Example:

DoWhile.java
int i = 1;

do {
    System.out.println(i);
    i++;
} while (i <= 5);
Output
1
2
3
4
5

Now look at this:

DoWhile.java
int i = 10;

do {
    System.out.println(i);
} while (i < 5);

Even though:

10 < 5

is false, it prints:

Output
10

because do executes first and the condition is checked afterward.

Easy memory trick

for      → condition + repetition
while    → check first, then execute
do-while → execute first, then check

Java OOPs ⭐
For QA Automation — Deep Explanation in Very Easy Language

OOPs is one of the most important parts of Java for QA automation.

When you start learning Selenium, TestNG, Page Object Model (POM), frameworks, etc., you will see classes, objects, methods, inheritance, interfaces, constructors, and encapsulation everywhere.

So don't just memorize definitions. Let's understand why they exist and how QA uses them.

First: What is OOPs?

OOP = Object-Oriented Programming

The basic idea is:

Instead of writing everything in one huge program, we organize our code using objects and classes.

For example, in a testing project, you might have:

LoginPage
HomePage
SearchPage
LoginTest
SearchTest

Each can be a separate Java class.

A simple way to visualize it:

Java Automation Project | ├── LoginPage ├── HomePage ├── SearchPage └── LoginTest

OOPs gives us ways to organize and reuse this code.

Suite 10

10. Class & Object

This is the first OOP concept you should understand properly.

What is a Class?

A class is like a blueprint/design.

Imagine you want to build houses.

The architect creates a blueprint:

House Blueprint ├── color ├── doors ├── windows └── rooms

The blueprint itself isn't a house.

It describes what a house should contain.

Similarly:

Car.java
class Car {
    String color;
    String model;

    void drive() {
        System.out.println("Car is driving");
    }
}

Car is a class.

It describes what a car has and what a car can do.

What is an Object?

An object is the actual thing created from the class.

Car.java
Car myCar = new Car();

Here:

Car        → class/type
myCar     → object reference
new Car() → creates the object

Now you can use the object:

Car.java
myCar.color = "Red";
myCar.model = "Honda";

myCar.drive();
Easy example

Think:

Class  = Mobile design
Object = Actual Samsung phone
Object = Actual iPhone
Object = Actual OnePlus phone

One class can create multiple objects.

Car.java
Car car1 = new Car();
Car car2 = new Car();
Car car3 = new Car();

All three are objects of the Car class.

QA Example

Imagine a login page.

LoginPage.java
class LoginPage {

Remember:

Class  = blueprint

11. Constructor

A constructor is a special block that runs automatically when an object is created.

Example:

Student.java
class Student {

    Student() {
        System.out.println("Student object created");
    }
}

Now:

Student.java
Student s = new Student();
Output
Student object created

You didn't call:

s.Student();

The constructor automatically executed when:

new Student()

was used.

Constructor rules

A constructor:

Has the same name as the class
Has no return type
Runs automatically when an object is created

Example:

Car.java
class Car {

    Car() {
        System.out.println("Car created");
    }
}

Correct.

But this:

void Car()

is not a constructor. It's a method.

Why do we need constructors?

Constructors are commonly used to initialize data.

Example:

Student.java
class Student {

    String name;
    int age;

    Student(String studentName, int studentAge) {
        name = studentName;
        age = studentAge;
    }
}

Now:

Student.java
Student s1 = new Student("Monika", 25);

The constructor initializes:

name = Monika
age = 25

You can then access:

Student.java
System.out.println(s1.name);
System.out.println(s1.age);

Default Constructor

If you don't create any constructor yourself:

Student.java
class Student {
}

Java provides a default constructor automatically.

So:

Student s = new Student();

works.

But once you create your own constructor, Java doesn't automatically provide the no-argument constructor.

12. this Keyword

this is one of those concepts that looks confusing initially.

The simplest meaning is:

this refers to the current object.

Consider:

Student.java
class Student {

    String name;

    Student(String name) {
        this.name = name;
    }
}

There are two names:

this.name → class variable
name      → constructor parameter

So:

this.name = name;

means:

Store the parameter name inside the current object's name variable.

Without this

Consider:

Student.java
class Student {

    String name;

    Student(String studentName) {
        name = studentName;
    }
}

This works perfectly.

But often developers use the same name:

Student(String name)

Then this makes it clear:

this.name = name;

Visualize it

class Student name ← object variable ↑ | this.name name ← constructor parameter

So:

this.name = name;

means:

object's name = received name

Suite 13

13. Inheritance

Inheritance means:

One class can acquire properties and methods of another class.

Imagine:

Animal | ├── Dog └── Cat

Dog and Cat are animals.

So instead of repeating common functionality, we can put it in Animal.

Animal.java
class Animal {

    void eat() {
        System.out.println("Animal is eating");
    }
}

Now:

Dog.java
class Dog extends Animal {

    void bark() {
        System.out.println("Dog is barking");
    }
}

Here:

extends

means inheritance.

Now:

Dog.java
Dog d = new Dog();

d.eat();
d.bark();
Output
Animal is eating
Dog is barking

The Dog class inherited eat() from Animal.

Why inheritance is useful in QA

Imagine you have:

BaseTest | ├── LoginTest ├── SearchTest └── PaymentTest

Suppose BaseTest contains common setup:

BaseTest.java
class BaseTest {

    void openBrowser() {
        System.out.println("Opening browser");
    }
}

Then:

LoginTest.java
class LoginTest extends BaseTest {

    void loginTest() {
        System.out.println("Testing login");
    }
}

Now LoginTest can use:

LoginTest.java
openBrowser();
loginTest();

You don't need to duplicate openBrowser() in every test class.

This is a common idea in automation frameworks.

14. Polymorphism

This word looks difficult, but the idea is simple.

Poly = many

Morph = forms

So:

One thing can have multiple forms.

For example:

Animal | ├── Dog └── Cat

Both are animals, but they behave differently.

Animal.java
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}
Dog.java
class Dog extends Animal {

    void sound() {
        System.out.println("Dog barks");
    }
}
Cat.java
class Cat extends Animal {

    void sound() {
        System.out.println("Cat meows");
    }
}

Now:

Main.java
Animal a1 = new Dog();
Animal a2 = new Cat();

a1.sound();
a2.sound();
Output
Dog barks
Cat meows

Same method:

sound()

but different behavior.

That's polymorphism.

Two types of Polymorphism

You should remember these:

Polymorphism | ├── Compile-time | ↓ | Method Overloading | └── Runtime ↓ Method Overriding

Let's understand both.

Suite 15

15. Method Overloading

Method overloading means:

Same method name but different parameters.

Example:

Calculator.java
class Calculator {

    int add(int a, int b) {
        return a + b;
    }

    int add(int a, int b, int c) {
        return a + b + c;
    }
}

Both methods are called:

add()

but their parameters are different.

Main.java
Calculator c = new Calculator();

System.out.println(c.add(10, 20));
System.out.println(c.add(10, 20, 30));
Output
30
60

Java determines which method to call based on the arguments.

Overloading can differ by:

Number of parameters

LoginPage.java
login(String username)

login(String username, String password)

Type of parameters

Calculator.java
add(int a, int b)

add(double a, double b)

But this alone is not enough:

Calculator.java
int add(int a, int b)
double add(int a, int b)

You cannot overload methods only by changing the return type.

Method Overriding

Overriding happens when a child class provides its own implementation of a method inherited from the parent.

Parent:

Animal.java
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}

Child:

Dog.java
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

Now:

Main.java
Dog d = new Dog();

d.sound();
Output
Dog barks

The child has overridden the parent's sound() method.

Overloading vs Overriding

This is a very common interview question.

OverloadingOverriding
Same class generallyParent-child relationship
Same method nameSame method name
Parameters must differParameters must be same
Compile-time polymorphismRuntime polymorphism
Example: add(a,b) and add(a,b,c)Child changes parent's method
Easy memory:

Overloading
→ Same name
→ Different inputs

Overriding
→ Parent method
→ Child changes behavior

16. Encapsulation

Encapsulation means:

Wrapping data and methods together and controlling access to the data.

A common example is a bank account.

You don't want everyone to directly change your balance:

BankAccount.java
balance = 1000000;

Instead, you make the variable private.

BankAccount.java
class BankAccount {

    private double balance;

    public void setBalance(double balance) {
        this.balance = balance;
    }

    public double getBalance() {
        return balance;
    }
}

Now:

Main.java
BankAccount account = new BankAccount();

account.setBalance(5000);

System.out.println(account.getBalance());
Output
5000

Why private?

Because this:

Main.java
account.balance = 100000;

will not be allowed if balance is private.

Instead, you control access through:

setBalance()
getBalance()

These are commonly called:

Getter → gets the value
Setter → sets/changes the value

QA example of Encapsulation

Suppose you have:

LoginPage.java
class LoginPage {

    private String username;

    public void setUsername(String username) {
        this.username = username;
    }

    public String getUsername() {
        return username;
    }
}

Now the data is controlled instead of being directly exposed.

This idea becomes important in Page Object Model and framework design.

17. Abstraction

Abstraction means:

Hide unnecessary implementation details and show only what is necessary.

Think about driving a car.

You know:

Start
Accelerate
Brake
Steer

But you don't need to understand every internal engine operation to drive the car.

That's abstraction.

Java example

Vehicle.java
abstract class Vehicle {

    abstract void start();

    void stop() {
        System.out.println("Vehicle stopped");
    }
}

Here:

abstract void start();

doesn't contain implementation.

It says:

Every vehicle must have a start() method.

A child class provides the implementation:

Car.java
class Car extends Vehicle {

    @Override
    void start() {
        System.out.println("Car starts with key");
    }
}

Now:

Main.java
Car car = new Car();

car.start();
car.stop();
Output
Car starts with key
Vehicle stopped

18. Interface

An interface is like a contract.

It tells a class:

"If you implement me, you must provide these required behaviors."

Example:

Animal.java
interface Animal {

    void sound();
}

Now:

Dog.java
class Dog implements Animal {

    @Override
    public void sound() {
        System.out.println("Dog barks");
    }
}

Notice:

implements

is used with interfaces.

Interface vs Class

Think:

Interface ↓ Contract / rules Class ↓ Implementation

For example:

Payment.java
interface Payment {

    void pay();
}

Different payment systems can implement it:

CreditCard.java
class CreditCard implements Payment {

    public void pay() {
        System.out.println("Paid using credit card");
    }
}
UPI.java
class UPI implements Payment {

    public void pay() {
        System.out.println("Paid using UPI");
    }
}

Both follow the same contract:

Payment | ├── CreditCard └── UPI

But their implementation is different.

⭐ Very Important QA Connection: Selenium

This is where OOP becomes really interesting for you.

In Selenium, you'll see things like:

Test.java
WebDriver driver;

WebDriver is an interface.

Different browser drivers implement it.

Conceptually:

WebDriver | ├── ChromeDriver ├── FirefoxDriver └── EdgeDriver

So you can write:

Test.java
WebDriver driver = new ChromeDriver();

Later:

Test.java
WebDriver driver = new FirefoxDriver();

Your test code can work with the common WebDriver interface.

This is one reason understanding interfaces and polymorphism is important for QA automation.

20. Exception Handling ⭐⭐⭐

What is an Exception?

An exception is an unexpected problem that happens while a program is running.

For example:

Divide.java
int a = 10;
int b = 0;

System.out.println(a / b);

You cannot divide by zero.

Java will produce an exception:

ArithmeticException

If you don't handle it, the program may stop.

Real-life example

Imagine you're testing a login page.

Your automation says:

1. Open website
2. Find username field
3. Enter username
4. Click Login

But suppose the username field isn't present.

Your test encounters an error.

Instead of letting the whole program crash unexpectedly, exception handling allows you to handle the problem gracefully.

try-catch

Basic syntax:

Syntax.java
try {
    // risky code
}
catch (Exception e) {
    // handle exception
}

Example:

Main.java
public class Main {

    public static void main(String[] args) {

        try {
            int result = 10 / 0;
            System.out.println(result);
        }
        catch (Exception e) {
            System.out.println("Something went wrong");
        }
    }
}
Output
Something went wrong

The program doesn't simply crash.

Understanding try

Put the code that might cause an exception inside try.

Try.java
try {
    int result = 10 / 0;
}

Understanding catch

catch handles the exception.

Catch.java
catch (Exception e) {
    System.out.println("Error occurred");
}

Here:

Exception → type of exception
e          → variable containing exception information

You can print the actual error:

Catch.java
catch (Exception e) {
    System.out.println(e);
}

Specific Exception

Instead of catching everything:

Catch.java
catch (Exception e)

you can catch a specific exception:

Specific.java
try {
    int result = 10 / 0;
}
catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
}

This is generally better when you know what you're expecting.

Multiple catch blocks

You can handle different exceptions differently.

Multiple.java
try {

    int[] numbers = {10, 20, 30};

    System.out.println(numbers[5]);

}
catch (ArrayIndexOutOfBoundsException e) {

    System.out.println("Invalid array index");

}
catch (Exception e) {

    System.out.println("Some other error");

}

finally

finally executes whether an exception occurs or not, with some language/runtime caveats.

Example:

Finally.java
try {
    System.out.println("Opening browser");
}
catch (Exception e) {
    System.out.println("Error");
}
finally {
    System.out.println("Closing browser");
}
Output
Opening browser
Closing browser
QA example

A common automation pattern is:

Open browser ↓ Run test ↓ Exception? ↙ ↘ Yes No ↓ ↓ Handle Continue \ / ↓ Close browser

finally can be useful for cleanup.

throw

throw is used when you want to manually create/raise an exception.

Example:

Throw.java
int age = 15;

if (age < 18) {
    throw new IllegalArgumentException("Age must be 18 or above");
}

You are explicitly saying:

Something is wrong, so throw an exception.

throws

throws is different.

It tells the caller:

This method may produce this exception, so whoever calls me should handle it.

Example:

Throws.java
void readFile() throws IOException {
    // file operations
}
Easy difference:

throw
→ actually throws an exception

throws
→ declares that a method may throw an exception

28. Access Modifiers ⭐⭐⭐

Access modifiers control who can access something.

The four important ones are:

public
private
protected
default

public

Accessible from anywhere where the class is accessible.

Login.java
public void login() {
}

private

Accessible only inside the same class.

Login.java
private String password;

This is very useful for encapsulation.

For example:

Login.java
class Login {

    private String password;
}

Other classes cannot directly access password.

protected

Accessible within the same package and also by subclasses under Java's inheritance access rules.

Example:

Base.java
protected void setup() {
}

This is sometimes used in test frameworks with base classes.

default

If you don't write an access modifier:

Login.java
void login() {
}

it has package-private/default access.

It can be accessed within the same package.

Why File Handling Matters in QA

Imagine you have 100 test cases.

You don't want to hard-code everything:

HardCoded.java
login("user1", "pass1");
login("user2", "pass2");
login("user3", "pass3");

Instead, you can store test data in files.

For example:

testdata.csv
username,password
user1,pass1
user2,pass2
user3,pass3

Your automation can read this data and execute tests.

Later, you'll learn specialized libraries/tools for:

Excel      → Apache POI
JSON       → Jackson/Gson
CSV        → CSV libraries
Properties → Properties class

So for now, understand the basic Java file concept, not every library.

Phase 3 · Summary

🧪 Let's Combine Phase 3

Here's a small program that uses several concepts together:

LoginTest.java
import java.util.ArrayList;
import java.util.HashMap;

public class LoginTest {

    public static void main(String[] args) {

        ArrayList users = new ArrayList<>();

        users.add("Monika");
        users.add("Rahul");
        users.add("Priya");

        HashMap loginData = new HashMap<>();

        loginData.put("username", "monika");
        loginData.put("password", "12345");

        for (String user : users) {

            try {

                System.out.println("Testing login for: " + user);

                String username = loginData.get("username");
                String password = loginData.get("password");

                System.out.println("Username: " + username);
                System.out.println("Password: " + password);

            }
            catch (Exception e) {

                System.out.println("Login test failed");
            }
        }
    }
}

Here you've used:

ArrayList ↓ Stores multiple users HashMap ↓ Stores key-value test data for loop ↓ Runs test for each user try-catch ↓ Handles unexpected errors methods/classes ↓ Organize the code

This is starting to look like real automation programming.

⭐ Phase 3 — What You Should Focus on Most

For your goal of becoming a QA Automation Engineer, prioritize these:

🔥 Must understand very well

1. Exception Handling — Especially: try, catch, finally, throw, throws

2. Collections — Understand the difference between List, Set, Map

3. ArrayList — Very common.

4. HashMap — Extremely useful for test data.

5. Loops with Collections — Very common in automation.

6. Methods — You will use methods everywhere.

7. Access Modifiers — Especially: private, public, protected

8. static — Understand class-level vs object-level members.

9. Packages — Important for framework structure.

10. File Handling — Understand the basic concept; later you'll learn Excel/JSON/CSV-specific handling.

Phase 3 · Where this leads

🎯 How Phase 3 Connects to Selenium

Eventually, you may write something conceptually like:

Selenium.java
List links = driver.findElements(By.tagName("a"));

for (WebElement link : links) {

    System.out.println(link.getText());
}

Look carefully.

You have:

List ↓ WebElements ↓ for loop ↓ getText()

That's Collections + Loops + Methods + Selenium working together.

Another example:

Selenium.java
Map testData = new HashMap<>();

testData.put("username", "monika");
testData.put("password", "12345");

Then:

Selenium.java
driver.findElement(...).sendKeys(testData.get("username"));

That's why learning these Java concepts before Selenium is such a good approach.
